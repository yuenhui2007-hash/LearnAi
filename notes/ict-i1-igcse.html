📘 IGCSE Content

Hardware Components

  • CPU (Central Processing Unit): ALU (Arithmetic Logic Unit), CU (Control Unit), Registers
  • RAM (Random Access Memory): Volatile; stores currently running programs and data
  • ROM (Read Only Memory): Non-volatile; stores BIOS/firmware
  • Hard Disk/SSD: Secondary storage; persistent data
  • Input devices: Keyboard, mouse, scanner, microphone, webcam
  • Output devices: Monitor, printer, speakers, projector

How the CPU Works

  • Fetch-Decode-Execute cycle: Instructions fetched from memory, decoded by CU, executed by ALU
  • Clock speed: Measured in GHz; cycles per second
  • Cores: Multiple processing units for parallel tasks

📗 AS Level Content

Storage Technologies

  • Magnetic: Hard disks — high capacity, mechanical, slower
  • Optical: CD, DVD, Blu-ray — removable, lower capacity
  • Solid State: SSD, flash drives — no moving parts, faster, more expensive
  • Cloud storage: Remote servers accessed via internet

Factors Affecting Performance

  • Clock speed, number of cores, cache size, RAM amount, storage type

📙 A2 Level Content

System Architecture

  • von Neumann architecture: Stored program concept; data and instructions in same memory
  • Harvard architecture: Separate memory for data and instructions
  • Cache memory: L1 (fastest, smallest), L2, L3

💻 Worked Example

Question: Convert denary 157 to 8-bit binary.

Solution:
128 + 16 + 8 + 4 + 1 = 157
1 0 0 1 1 1 0 1
Answer: 10011101
Confusing bits and bytes. 1 byte = 8 bits. File sizes in bytes; transfer speeds in bits.
Fetch-decode-execute: 1) Fetch instruction from memory, 2) Decode operation, 3) Execute. Repeats millions of times/second.

⚡ Quick Recall

  • CPU: ALU + CU + Registers
  • RAM: Volatile; ROM: Non-volatile
  • LAN: Local; WAN: Wide
  • Binary to hex: Group in 4s from right
