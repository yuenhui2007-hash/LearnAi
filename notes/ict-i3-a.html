Data Representation & Binary

📘 IGCSE Content

Number Systems

  • Binary (base 2): 0 and 1; computers use binary
  • Denary (base 10): 0–9; human-readable
  • Hexadecimal (base 16): 0–9, A–F; compact representation of binary

Binary Conversion

Binary to denary: 1011 = 1×8 + 0×4 + 1×2 + 1×1 = 11
Denary to binary: Repeated division by 2, remainders read upwards

Binary Arithmetic

  • Addition: 0+0=0, 0+1=1, 1+1=10 (carry 1)
  • Overflow: Result exceeds available bits

Character Encoding

  • ASCII: 7 bits; 128 characters
  • Unicode: Variable length; supports all world languages

📗 AS Level Content

Binary Representations

  • Integers: Signed (two's complement) vs unsigned
  • Floating point: Mantissa and exponent; IEEE 754 standard
  • Images: Bitmap (pixels) vs Vector (mathematical shapes)

Two's Complement

Positive 5: 00000101
Negative 5: invert + 1 → 11111011

📙 A2 Level Content

Data Compression

  • Lossless: Run-length encoding, Huffman coding — no data lost
  • Lossy: JPEG, MP3 — removes imperceptible data

Sound Representation

  • Sampling rate: Measurements per second (Hz)
  • Bit depth: Bits per sample
  • File size: Sample rate × bit depth × duration × channels

💻 Worked Example

Question: Convert denary 157 to 8-bit binary.

Solution:
128 + 16 + 8 + 4 + 1 = 157
1 0 0 1 1 1 0 1
Answer: 10011101
Confusing bits and bytes. 1 byte = 8 bits. File sizes in bytes; transfer speeds in bits.
Fetch-decode-execute: 1) Fetch instruction from memory, 2) Decode operation, 3) Execute. Repeats millions of times/second.

⚡ Quick Recall

  • CPU: ALU + CU + Registers
  • RAM: Volatile; ROM: Non-volatile
  • LAN: Local; WAN: Wide
  • Binary to hex: Group in 4s from right
