📘 IGCSE Content

1.1 Types of Software

  • System software: Manages hardware and provides platform for applications. Includes operating systems, device drivers, utilities.
  • Application software: Programs users run to perform tasks. General-purpose (word processor, spreadsheet) or special-purpose (payroll, booking system).

1.2 Operating System (OS) Functions

The OS is the intermediary between user and hardware. Core functions:

  • Memory management: Allocates RAM to processes; virtual memory; paging/segmentation.
  • Processor management: Scheduling (FIFO, SJF, round robin, priority); multitasking; interrupt handling.
  • File management: Organizes storage with directories/folders; file permissions; maintains file allocation table.
  • Device management: Controls peripherals via device drivers; buffers and spooling (e.g., print queue).
  • Security: User accounts, passwords, access rights, encryption.
  • User interface: GUI (windows, icons, menus, pointers), CLI (command line), voice, touch.

1.3 Utility Programs

  • Disk defragmenter: Reorganizes fragmented files into contiguous blocks on HDD. Improves read speed. Not needed for SSDs.
  • Disk cleanup: Removes temporary files, recycle bin contents, cache.
  • Backup software: Copies data to secondary location. Full, incremental, differential strategies.
  • Compression utilities: Reduce file size (ZIP, RAR) for storage or transmission.
  • Antivirus / Anti-malware: Scans, detects, quarantines threats.
  • Firewall: Filters network traffic.
  • System monitors: Task Manager, Resource Monitor — show CPU, RAM, disk, network usage.

1.4 Application Software Types

  • Word processing: Create, edit, format text documents. Features: spell check, mail merge, styles, tables, macros. Examples: Microsoft Word, Google Docs.
  • Spreadsheets: Grid of cells for calculations, charts, data analysis. Features: formulas, functions, pivot tables, conditional formatting. Examples: Excel, Google Sheets.
  • Presentation: Slides with text, images, animations. Examples: PowerPoint, Google Slides.
  • Database management: Store, query, and manage structured data. Examples: Access, MySQL, FileMaker.
  • Web browsers: Access and render web pages. Examples: Chrome, Firefox, Edge, Safari.
  • Email clients: Send/receive/manage emails. Examples: Outlook, Thunderbird, Apple Mail.
  • Graphics editing: Bitmap (Photoshop, GIMP) and vector (Illustrator, Inkscape).
  • Video editing: Timeline-based editing, transitions, effects. Examples: Premiere Pro, DaVinci Resolve, iMovie.

📗 AS Level Content

2.1 OS Scheduling Algorithms

  • First-Come First-Served (FCFS): Simple queue. Easy to implement but can cause convoy effect (short jobs wait behind long ones).
  • Shortest Job First (SJF): Minimizes average waiting time. Requires prediction of burst time. Can starve long jobs.
  • Round Robin: Fixed time quantum (e.g., 10ms) per process; cycles through queue. Fair, good response time; context-switch overhead.
  • Priority Scheduling: Highest priority runs first. Can be preemptive or non-preemptive. Risk of starvation for low-priority processes.
  • Multilevel Queue: Multiple queues with different priorities (e.g., system, interactive, batch, student).

2.2 Memory Management Techniques

  • Single contiguous allocation: Entire memory to one program. Simple but wasteful.
  • Partitioned allocation: Fixed partitions (wastes space if program smaller) or dynamic partitions (fragmentation).
  • Paging: Physical memory divided into fixed-size frames; logical memory into same-size pages. Page table maps pages to frames. Eliminates external fragmentation.
  • Segmentation: Logical memory divided into variable-size segments (code, data, stack). Segment table maps segments to physical addresses. Matches program structure but can cause external fragmentation.
  • Virtual memory: Uses disk as extension of RAM. Page fault = needed page not in RAM; OS fetches from disk. Thrashing = excessive page faults degrade performance.

2.3 File Systems & Storage

  • FAT32: Older, compatible everywhere. 4GB max file size, 2TB max partition. No journaling.
  • NTFS (Windows): Journaling, encryption (EFS), compression, permissions, large file support.
  • ext4 (Linux): Journaling, extents, large volume/file support, backward compatible.
  • APFS (macOS): Optimized for SSDs, snapshots, encryption, space sharing.
  • Journaling: Logs changes before applying them. Prevents corruption from power failure.

2.4 Translation Software

  • Compiler: Translates entire high-level program to machine code before execution. Output = executable file. Slower compilation but faster execution. Detects syntax errors. Examples: GCC, MSVC, Clang.
  • Interpreter: Translates and executes line-by-line. No separate executable. Easier debugging but slower execution. Examples: Python interpreter, JavaScript engine.
  • Assembler: Translates assembly language (mnemonics like MOV, ADD) into machine code (one-to-one). Used for low-level programming.
  • JIT (Just-In-Time) Compiler: Hybrid — compiles bytecode to machine code at runtime. Used by Java (JVM) and C# (.NET CLR).

2.5 Software Licensing

  • Proprietary/Commercial: Closed source; user buys license. Source code not available. Examples: Microsoft Office, Adobe Creative Suite.
  • Open Source: Source code available; can modify and redistribute. Examples: Linux, LibreOffice, GIMP.
  • Freeware: Free to use but source not available. Examples: Skype (originally), Adobe Reader.
  • Shareware: Free trial with limited features or time; pay to unlock. Examples: WinRAR.
  • FOSS (Free and Open Source Software): Free as in freedom (GPL, MIT, Apache licenses).

📙 A2 Level Content

3.1 Real-Time Operating Systems (RTOS)

Guarantees response within strict time constraints. Used in embedded systems, medical devices, automotive, aerospace.

  • Hard real-time: Missing deadline = system failure (e.g., pacemaker, airbag controller).
  • Soft real-time: Missing deadline degrades quality but does not crash (e.g., video streaming, MP3 player).

Features: deterministic scheduling, minimal interrupt latency, priority inheritance, no virtual memory (avoids page faults).

3.2 Distributed Operating Systems

Manages a group of independent computers as a single coherent system. Users perceive it as one machine. Examples: Google File System, Apache Hadoop. Challenges: consensus algorithms, CAP theorem (Consistency, Availability, Partition tolerance — pick two), fault tolerance.

3.3 System Development Life Cycle (SDLC)

  • Waterfall: Linear sequential phases (requirements → design → implementation → testing → deployment → maintenance). Easy to manage; rigid; hard to change requirements later.
  • Agile/Scrum: Iterative sprints (2–4 weeks). Continuous feedback; adaptive; customer collaboration. Roles: Product Owner, Scrum Master, Development Team. Artifacts: Product Backlog, Sprint Backlog, Burndown Chart.
  • Spiral: Risk-driven; combines iterative with systematic risk analysis.
  • RAD (Rapid Application Development): Prototyping focus; quick iterations; user feedback throughout.

3.4 Software Testing

  • White-box: Tester sees internal code. Tests paths, branches, loops. Measures code coverage.
  • Black-box: Tester sees only inputs/outputs. Tests requirements, boundaries, equivalence partitions.
  • Unit testing: Individual functions/modules. Automated with frameworks (JUnit, pytest).
  • Integration testing: Modules combined; test interfaces.
  • System testing: Complete system against specifications.
  • Acceptance testing: User/client validates against business needs.
  • Alpha testing: Internal, controlled environment.
  • Beta testing: Released to external users for real-world feedback.

3.5 Virtualisation & Containers

  • Virtual Machine (VM): Software emulation of a complete computer. Hypervisor (Type 1 = bare metal like VMware ESXi; Type 2 = hosted like VirtualBox) manages VMs. Each VM has its own OS. Heavy resource use.
  • Containers (Docker): Share host OS kernel; package only app + dependencies. Lightweight, fast startup, consistent across environments. Orchestrated by Kubernetes.

📘 IGCSE Content

1.1 Flat-File vs Relational Databases

  • Flat-file database: Single table. All data in one place. Simple but causes data redundancy and inconsistency. Example: a single spreadsheet with student records including repeated teacher names.
  • Relational database: Multiple linked tables. Data split logically to avoid duplication. Relationships connect tables via keys. Example: Students table + Teachers table + Classes table.

1.2 Key Database Terms

  • Table/Relation: Collection of related records (rows).
  • Record/Row/Tuple: One complete set of data (e.g., one student).
  • Field/Column/Attribute: One type of data (e.g., FirstName, DateOfBirth).
  • Primary Key: Unique identifier for each record (e.g., StudentID). Cannot be null; must be unique.
  • Foreign Key: Field in one table that links to the primary key in another table. Creates relationships.
  • Composite Key: Primary key made of two or more fields combined.
  • Candidate Key: Any field or combination that could uniquely identify a record.

1.4 Database Relationships

  • One-to-One (1:1): One record in Table A links to exactly one in Table B. Example: Student → StudentDetails.
  • One-to-Many (1:M): One record in Table A links to many in Table B. Example: One Teacher teaches many Classes.
  • Many-to-Many (M:N): Many records in Table A link to many in Table B. Requires a junction/link table. Example: Students enroll in many Courses; Courses have many Students.

1.5 Validation Techniques

  • Range check: Value must be within specified limits (e.g., age 0–120).
  • Type check: Data must match expected type (e.g., integer in a number field).
  • Length check: Data must be certain length (e.g., postcode 5–7 characters).
  • Presence check: Field cannot be left empty (e.g., email required).
  • Format check: Data matches a pattern (e.g., email regex, date DD/MM/YYYY).
  • Lookup/list check: Value must be from a predefined list (e.g., country dropdown).
  • Check digit: Extra digit calculated from others (e.g., ISBN, barcode) to detect transcription errors.

1.6 Querying a Database

A query retrieves specific data based on criteria. In a query-by-example (QBE) interface:

  • Select fields to display.
  • Set criteria (e.g., Grade = "A", Age > 18).
  • Sort ascending or descending.
  • Use AND/OR logic for multiple criteria.

📗 AS Level Content

2.1 Normalisation

Process of organizing data to reduce redundancy and improve integrity.

  • First Normal Form (1NF): Atomic values (no repeating groups), each cell contains single value, primary key defined.
    Example: Remove multiple phone numbers in one cell; create separate Phone table.
  • Second Normal Form (2NF): Must be in 1NF + no partial dependency (non-key attributes depend on entire primary key, not just part). Only relevant for composite keys.
    Example: In (StudentID, CourseID) → Grade, InstructorName depends only on CourseID → move InstructorName to Course table.
  • Third Normal Form (3NF): Must be in 2NF + no transitive dependency (non-key attributes depend only on primary key, not on other non-key attributes).
    Example: StudentID → Department → DepartmentHead. DepartmentHead depends on Department, not directly on StudentID → create Department table.

2.2 SQL (Structured Query Language)

Standard language for relational database management.

-- Retrieve all columns for students aged over 18
SELECT * FROM Students WHERE Age > 18;

-- Retrieve specific columns, sorted
SELECT FirstName, LastName, Grade FROM Students
WHERE Grade IN ('A','B')
ORDER BY LastName ASC;

-- Join two tables
SELECT Students.FirstName, Classes.ClassName
FROM Students
INNER JOIN Enrollments ON Students.StudentID = Enrollments.StudentID
INNER JOIN Classes ON Enrollments.ClassID = Classes.ClassID;

-- Aggregate functions
SELECT COUNT(*) FROM Students;
SELECT AVG(Score) FROM Exams WHERE Subject = 'Math';
SELECT Department, MAX(Salary) FROM Employees GROUP BY Department HAVING MAX(Salary) > 50000;

2.4 Entity-Relationship Diagrams (ERDs)

Visual representation of database structure:

  • Entities: Represented as rectangles (tables).
  • Attributes: Listed inside entity or as ovals.
  • Relationships: Diamonds or lines connecting entities.
  • Cardinality: 1:1, 1:M, M:N shown on relationship lines.
  • Crow's foot notation: Single line = one, crow's foot = many, circle = zero.

2.5 Referential Integrity

  • Cascade Update: If primary key changes, foreign keys update automatically.
  • Cascade Delete: If parent record deleted, child records delete automatically.
  • Restrict/No Action: Prevents deletion of parent if children exist.
  • Set Null: Sets foreign key to NULL if parent deleted (when allowed).

📙 A2 Level Content

3.1 Database Management Systems (DBMS)

Software managing databases: MySQL, PostgreSQL, Oracle, Microsoft SQL Server, MongoDB (NoSQL). Features:

  • ACID properties: Atomicity (all or nothing), Consistency (valid state), Isolation (transactions don't interfere), Durability (committed data survives crashes).
  • Concurrency control: Locking (pessimistic) vs Multiversion Concurrency Control MVCC (optimistic). Prevents lost updates, dirty reads, non-repeatable reads.
  • Transaction logs: Write-ahead logging for recovery after system failure.

3.2 Indexing & Query Optimisation

  • Index: Data structure (B-tree, hash) speeding up searches. Like a book index.
  • Primary index on primary key; secondary index on frequently searched columns.
  • Trade-off: indexes speed reads but slow writes (index must update).
  • Query optimiser: DBMS analyses SQL and chooses most efficient execution plan (which index, join order, scan type).

3.3 Relational Algebra

Mathematical foundation of SQL. Operations:

  • Selection (σ): Horizontal subset — choose rows meeting condition. σAge>18(Students)
  • Projection (π): Vertical subset — choose columns. πFirstName,LastName(Students)
  • Union (∪): Combine two compatible tables, remove duplicates.
  • Difference (−): Rows in one table but not the other.
  • Intersection (∩): Rows common to both tables.
  • Cartesian Product (×): All combinations of rows from two tables.
  • Join (⋈): Combine related rows from two tables. Natural join matches common columns; theta join matches arbitrary condition.

3.4 NoSQL & Big Data

  • Document stores (MongoDB): JSON-like documents, flexible schema, horizontal scaling.
  • Key-value stores (Redis): Simple key-value pairs, extremely fast caching.
  • Column-family (Cassandra, HBase): Optimized for massive write throughput.
  • Graph databases (Neo4j): Nodes and edges; ideal for social networks, recommendation engines.
  • CAP Theorem: Consistency, Availability, Partition Tolerance — distributed systems can guarantee at most two simultaneously.

3.5 Data Protection & Ethics

  • GDPR principles: Lawfulness, fairness, transparency, purpose limitation, data minimization, accuracy, storage limitation, integrity/confidentiality, accountability.
  • Data anonymisation: Remove personally identifiable information (PII) for analysis.
  • Encryption at rest and in transit: Protect sensitive database fields (e.g., passwords hashed with bcrypt/Argon2, credit cards encrypted).
  • Audit trails: Log who accessed what data and when — essential for compliance.

📘 IGCSE Content

1.1 How the Web Works

  • Client-server model: Browser (client) requests pages; web server (e.g., Apache, Nginx, IIS) responds with files.
  • HTTP (HyperText Transfer Protocol): Stateless request-response protocol. Port 80. HTTPS = encrypted via TLS, port 443.
  • URL anatomy: https://www.example.com:443/products?id=42 → protocol + subdomain + domain + TLD + port + path + query string.
  • DNS resolution: Browser checks cache → OS cache → router cache → ISP DNS → recursive query to authoritative DNS → IP address returned.
  • Web hosting: Shared (cheap, limited), VPS (virtual private), Dedicated (full server), Cloud (scalable, pay-as-you-go).

CSS (Cascading Style Sheets) controls presentation. Three ways to apply:

  • Internal: <style> in <head> — for single-page sites.
  • External: <link rel="stylesheet" href="styles.css"> — preferred for multi-page sites; separation of concerns.

property: value;

}

/* Examples */

1.5 CSS Selectors

  • Element: p, h1, div — selects all of that element.
  • Class: .classname — reusable; multiple elements can share.
  • ID: #idname — unique per page; highest specificity.
  • Descendant: div p — selects <p> inside <div>.
  • Child: div > p — direct child only.
  • Adjacent sibling: h1 + p — <p> immediately after <h1>.
  • Attribute: [type="submit"], [href^="https"] — based on attributes.
  • Pseudo-class: :hover, :focus, :nth-child(odd), :first-child.
  • Pseudo-element: ::before, ::after, ::first-line.

📗 AS Level Content

2.1 CSS Box Model

Every element is a rectangular box:

Total width = content width + padding-left + padding-right + border-left + border-right + margin-left + margin-right
box-sizing: border-box; /* includes padding and border in width */
  • Content: Text, images, or other media.
  • Padding: Space between content and border (inside the box).
  • Border: Line around padding. Properties: width, style (solid, dashed, dotted), color.
  • Margin: Space outside the border, separating elements. Margin collapse occurs when vertical margins overlap.

2.2 CSS Layout Techniques

  • Display property: block (full width), inline (within text flow), inline-block (inline but accepts dimensions), none (hidden), flex, grid.
  • Positioning:
    • Static: Default; normal document flow.
    • Relative: Offset from normal position (top, left, etc.).
    • Absolute: Positioned relative to nearest positioned ancestor.
    • Fixed: Relative to viewport; stays on screen when scrolling.
    • Sticky: Toggles between relative and fixed based on scroll position.
  • Float: Older layout method; moves element left/right with text wrapping. Clearfix needed. Largely replaced by Flexbox/Grid.
  • Flexbox: One-dimensional layout (row or column). Properties: display:flex, justify-content, align-items, flex-direction, flex-wrap, gap.
  • CSS Grid: Two-dimensional layout (rows and columns). Properties: display:grid, grid-template-columns, grid-template-rows, grid-gap, grid-area.

2.3 Responsive Web Design (RWD)

Websites adapt to different screen sizes:

  • Viewport meta tag: <meta name="viewport" content="width=device-width, initial-scale=1.0">
  • Media queries: Apply CSS conditionally based on device characteristics.
    @media screen and (max-width: 600px) {
    nav { flex-direction: column; }
    body { font-size: 14px; }
    }
  • Fluid layouts: Use percentages, vw/vh, fr units instead of fixed pixels.
  • Flexible images: max-width: 100%; height: auto; prevents overflow.
  • Mobile-first approach: Design for small screens first, then enhance for larger screens with min-width media queries.

3.2 Databases & Web Integration

  • CRUD operations: Create (INSERT), Read (SELECT), Update (UPDATE), Delete (DELETE).
  • SQL Injection: Malicious input manipulating queries. Prevention: parameterized queries/prepared statements.
    // Vulnerable
    $query = "SELECT * FROM Users WHERE username='" . $_GET['u'] . "'";

    // Secure (parameterized)

2.3 Searching Algorithms

  • Linear Search: Check each element in order from start to end. Simple; works on unsorted data. Time complexity: O(n).
    found = FALSE
    i = 0
    WHILE i < length AND NOT found
    IF array[i] = target THEN
    found = TRUE
    index = i
    ENDIF
    i = i + 1
    ENDWHILE
  • Binary Search: Requires sorted data. Repeatedly divides search interval in half. Time complexity: O(log n). Much faster for large datasets.
    low = 0
    high = length - 1
    found = FALSE
    WHILE low <= high AND NOT found
    mid = (low + high) DIV 2

    low = mid + 1
    ELSE

    ENDIF

2.4 Sorting Algorithms

  • Bubble Sort: Repeatedly swap adjacent elements if in wrong order. After each pass, largest unsorted element "bubbles" to end. Time: O(n²). Simple but inefficient.
    FOR pass = 1 TO n-1
    FOR i = 0 TO n-pass-1
    IF array[i] > array[i+1] THEN
    temp = array[i]
    array[i] = array[i+1]
    array[i+1] = temp
    ENDIF
    NEXT i
    NEXT pass
  • Insertion Sort: Build sorted array one element at a time. Take next element, insert into correct position in sorted portion. Time: O(n²) worst, O(n) best (already sorted). Efficient for small or nearly sorted data.
    FOR i = 1 TO n-1
    current = array[i]
    j = i - 1
    WHILE j >= 0 AND array[j] > current
    array[j+1] = array[j]
    j = j - 1
    ENDWHILE
    array[j+1] = current
    NEXT i

3.1 Advanced Sorting & Searching

  • Merge Sort: Divide-and-conquer. Split array in half recursively, sort each half, merge sorted halves. Time: O(n log n) in all cases. Stable sort. Requires O(n) extra space.
    MERGE_SORT(array):
    IF length <= 1 THEN RETURN array
    mid = length DIV 2
    left = MERGE_SORT(array[0:mid])
    right = MERGE_SORT(array[mid:length])
    RETURN MERGE(left, right)
    MERGE(left, right):
    result = []
    WHILE left not empty AND right not empty
    IF left[0] <= right[0] THEN append left[0] to result, remove left[0]
    ELSE append right[0] to result, remove right[0]
    append remaining elements
    RETURN result
  • Quick Sort: Divide-and-conquer. Choose pivot, partition array into elements < pivot and >= pivot, recursively sort partitions. Time: O(n log n) average, O(n²) worst (poor pivot choice). In-place (low space). Not stable.
  • Hashing: Map keys to array indices using hash function. Ideal search time: O(1). Collisions resolved by chaining (linked lists) or open addressing (probing).

3.2 Abstract Data Types (ADTs)

  • Stack: LIFO (Last In, First Out). Operations: PUSH (add to top), POP (remove from top), PEEK (view top). Used: undo operations, function call stack, expression evaluation, backtracking.
    Stack: []
    PUSH 5 → [5]
    PUSH 3 → [5, 3]
    POP → returns 3, stack is [5]
    PEEK → returns 5
  • Queue: FIFO (First In, First Out). Operations: ENQUEUE (add to rear), DEQUEUE (remove from front), FRONT (view front). Used: print queues, CPU scheduling, BFS traversal, buffering.
    Queue: []
    ENQUEUE A → [A]
    ENQUEUE B → [A, B]
    DEQUEUE → returns A, queue is [B]
  • Linked List: Nodes containing data and pointer to next node. Dynamic size. Types: singly linked (one pointer), doubly linked (previous and next), circular. No random access — must traverse from head.
  • Tree: Hierarchical structure. Root node, parent-child relationships. Binary Tree: each node has at most 2 children. Binary Search Tree (BST): left < parent < right. Enables efficient search, insertion, deletion (O(log n) balanced).

3.3 Graph Algorithms

  • Graph representation: Adjacency matrix (2D array, fast edge check, O(V²) space) or Adjacency list (linked lists per vertex, space-efficient for sparse graphs).
  • Breadth-First Search (BFS): Uses queue. Explores all neighbours at current depth before moving deeper. Finds shortest path in unweighted graphs.
  • Depth-First Search (DFS): Uses stack (or recursion). Explores as far as possible along each branch before backtracking. Used for maze solving, topological sort, cycle detection.
  • Dijkstra's Algorithm: Finds shortest path from source to all vertices in weighted graph with non-negative weights. Uses priority queue (min-heap). Time: O((V+E) log V).

3.4 Object-Oriented Programming (OOP)

  • Class: Blueprint defining attributes (data) and methods (behaviour).
  • Object: Instance of a class.
  • Encapsulation: Bundling data and methods; hiding internal state (private/protected); exposing interfaces (public methods/getters/setters).
  • Inheritance: Subclass derives from superclass, inheriting attributes and methods. Enables code reuse and "is-a" relationships. Example: Car inherits from Vehicle.
  • Polymorphism: Same interface, different implementations. Method overriding (subclass redefines parent method) and method overloading (same name, different parameters).
  • Abstraction: Simplifying complex reality by modelling classes appropriate to the problem.

3.5 Recursion

A function that calls itself. Must have:

  • Base case: Condition that stops recursion.
  • Recursive case: Function calls itself with a simpler sub-problem.
FUNCTION factorial(n)
IF n <= 1 THEN
RETURN 1
ELSE
RETURN n * factorial(n - 1)
ENDIF
ENDFUNCTION

Other examples: Fibonacci, binary search, merge sort, tree traversals, Tower of Hanoi.

Pros: Elegant, mirrors mathematical definitions, reduces code. Cons: Stack overflow risk, can be slower than iteration, harder to debug.

  • Access divide: Physical access to devices and internet infrastructure. Rural vs urban; developed vs developing countries.
  • Use divide: Skills and literacy to use ICT effectively. Older generations, low-education populations.
  • Quality divide: Speed and reliability of connection. Fibre vs dial-up; 5G vs 3G.

Consequences: Limited educational opportunities, reduced economic participation, social exclusion, poorer health outcomes. Solutions: public Wi-Fi, subsidized devices, digital literacy programs, infrastructure investment.

1.3 Health Issues

  • Physical: Repetitive Strain Injury (RSI) from keyboard/mouse use; eye strain from screens; back and neck pain from poor posture; obesity from sedentary lifestyle.
  • Mental: Internet addiction; social media anxiety and FOMO (Fear Of Missing Out); cyberbullying; sleep disruption from blue light exposure; reduced attention span from constant notifications.
  • Mitigation: Ergonomic furniture (adjustable chairs, wrist rests), regular breaks (20-20-20 rule: every 20 min, look 20 feet away for 20 seconds), screen filters, limiting screen time, physical exercise, digital wellness features (Screen Time, Focus modes).

1.4 Environmental Impact

  • Positive: Reduced paper use (dematerialization), remote work reducing transport emissions, smart grids optimizing energy use, precision agriculture reducing waste.
  • Negative: Energy consumption of data centres (2% of global electricity, rising), e-waste (53.6 million tonnes in 2019, only 17.4% recycled), rare earth mineral mining for electronics, carbon footprint of device manufacturing and shipping.
  • Solutions: Renewable-powered data centres, circular economy (repair, reuse, recycle), extended producer responsibility, cloud efficiency, longer device lifecycles.

📗 AS Level Content

2.1 Privacy & Data Protection

  • Personal data: Any information relating to an identified or identifiable natural person. Includes name, ID numbers, location data, online identifiers, biometric, genetic, health data.
  • Data protection principles (GDPR / similar laws):
    • Lawfulness, fairness, and transparency
    • Purpose limitation — collect for specified, explicit, legitimate purposes
    • Data minimization — adequate, relevant, limited to what is necessary
    • Accuracy — kept up to date; rectify inaccuracies
    • Storage limitation — kept no longer than necessary
    • Integrity and confidentiality — secure processing
    • Accountability — controller responsible for compliance
  • Individual rights: Right to be informed, access, rectification, erasure ("right to be forgotten"), restrict processing, data portability, object, rights related to automated decision-making.
  • Consent: Must be freely given, specific, informed, and unambiguous. Pre-ticked boxes are invalid.

2.2 Cybercrime & Legislation

  • Hacking: Unauthorized access to computer systems. Motivations: financial gain, espionage, activism (hacktivism), sabotage.
  • Identity theft: Stealing personal information to impersonate someone, often for financial fraud.
  • Computer Misuse Act 1990 (UK):
    • Section 1: Unauthorized access to computer material (basic hacking)
    • Section 2: Unauthorized access with intent to commit further offences
    • Section 3: Unauthorized acts with intent to impair operation of computer (malware, DDoS)
    • Section 3ZA: Unauthorized acts causing serious damage (national security, life-threatening)
  • Copyright, Designs and Patents Act 1988: Protects original works. Software is literary work. Prohibits copying, distributing, adapting without license. Fair dealing exceptions limited.
  • Other laws: Fraud Act, Data Protection Act, Regulation of Investigatory Powers Act, Digital Economy Act.

2.3 Ethical Issues

  • Surveillance: CCTV, facial recognition, phone tracking, internet monitoring by governments and corporations. Security vs privacy tension. Snowden revelations highlighted mass surveillance programs.
  • Censorship: Government blocking of websites, content removal, social media bans. Protects citizens from harm but can suppress free speech and dissent.
  • Artificial Intelligence bias: Algorithms trained on biased data produce discriminatory outcomes in hiring, lending, policing, criminal sentencing.
  • Automation & unemployment: AI and robotics replacing workers. Need for reskilling, universal basic income debates, new economic models.
  • Digital footprints: Every online action leaves traces. Permanent, searchable, potentially damaging to reputation. Right to be forgotten debates.

2.4 Intellectual Property

  • Copyright: Automatic protection for original creative works. No registration needed in most jurisdictions. Duration: author's life + 70 years.
  • Patents: Protect inventions. Must be novel, non-obvious, useful. Granted by patent office. Duration: typically 20 years. Software patents controversial.
  • Trademarks: Protect brands, logos, slogans. Distinctive signs of origin. Renewable indefinitely.
  • Trade secrets: Confidential business information (Coca-Cola formula). Protected by non-disclosure agreements.
  • Open source & Creative Commons: Alternative licensing allowing reuse with conditions (attribution, share-alike, non-commercial).

📙 A2 Level Content

3.1 Globalisation & ICT

ICT has accelerated globalisation by enabling instant communication, remote collaboration, and global supply chains.

  • Offshoring & outsourcing: Companies relocate operations to lower-cost countries enabled by reliable internet and communication tools. Benefits: cost reduction, 24-hour operations. Drawbacks: job losses in home country, quality control issues, exploitation concerns.
  • E-commerce: Global marketplaces (Amazon, Alibaba, eBay) connect buyers and sellers worldwide. Benefits: wider choice, lower prices, convenience. Challenges: counterfeit goods, consumer protection across borders, tax avoidance.
  • Digital currencies: Cryptocurrencies (Bitcoin, Ethereum) enable borderless transactions without intermediaries. Challenges: volatility, regulatory uncertainty, environmental cost of proof-of-work mining, use in illicit activities.

3.2 AI, Automation & the Future of Work

  • Industry 4.0: Smart factories using IoT, AI, robotics, big data analytics. Cyber-physical systems communicate and make decisions autonomously.
  • Job displacement: McKinsey estimates 800 million jobs could be automated by 2030. Most at risk: routine physical and cognitive tasks. Least at risk: creative, emotional intelligence, complex social interaction.
  • Job creation: New roles: AI trainers, data ethicists, drone operators, sustainability consultants, human-machine interaction designers.
  • Reskilling: Lifelong learning essential. Governments and companies invest in retraining programs. Micro-credentials and online certifications gain value.
  • UBI (Universal Basic Income): Proposed solution to technological unemployment. Regular unconditional payment to all citizens. Pilots in Finland, Kenya, Canada show mixed results.

3.3 Misinformation & Media Literacy

  • Fake news: Deliberately false information spread via social media and messaging apps. Motivations: political manipulation, financial gain (clickbait), entertainment.
  • Deepfakes: AI-generated realistic but fake video/audio. Threats to reputation, democracy, evidence integrity. Detection tools emerging but arms race continues.
  • Echo chambers & filter bubbles: Algorithms show content reinforcing existing beliefs. Polarization, radicalization risks.
  • Countermeasures: Fact-checking organizations, media literacy education, platform content moderation, algorithmic transparency, watermarking authentic content.

3.4 ICT in Development

  • M-Pesa (Kenya): Mobile money transforming financial inclusion in East Africa. No bank account needed. Model replicated globally.
  • Telemedicine in rural areas: Remote diagnosis via smartphones, connecting patients with specialists in cities.
  • Precision agriculture: Drones, sensors, and AI optimize irrigation and fertilizer use, increasing yields and conserving resources.
  • Challenges: Infrastructure gaps, electricity access, literacy barriers, local language support, affordability, sustainability of donor-funded projects.

3.5 Evaluating ICT Solutions

When assessing ICT systems or policies, consider:

  • Technical feasibility: Can it be built with current technology? Scalability?
  • Economic viability: Cost-benefit analysis, ROI, total cost of ownership (TCO).
  • Social impact: Who benefits? Who is excluded? Effect on communities and culture?
  • Ethical implications: Privacy, autonomy, fairness, transparency, accountability.
  • Legal compliance: Data protection, accessibility standards, industry regulations.
  • Environmental impact: Energy use, e-waste, lifecycle assessment.
  • Security: Risk assessment, threat modelling, resilience.

I10: Emerging Technologies

📘 IGCSE Content

1.1 What is Artificial Intelligence?

Artificial Intelligence (AI) is the simulation of human intelligence by machines. It involves systems that can perform tasks normally requiring human cognition: visual perception, speech recognition, decision-making, language translation.

  • Narrow/Weak AI: Designed for a specific task (e.g., chess engine, voice assistant, spam filter). Cannot generalize beyond its domain. All current AI is narrow AI.
  • General/Strong AI: Hypothetical AI with human-like general intelligence across all domains. Does not yet exist.
  • Superintelligence: AI surpassing human intelligence in virtually every field. Speculative; subject of debate among researchers (Bostrom, Kurzweil).

1.2 AI Applications

  • Virtual assistants: Siri, Alexa, Google Assistant — natural language processing, speech recognition, task automation.
  • Recommendation systems: Netflix, Spotify, Amazon — collaborative filtering, content-based filtering.
  • Computer vision: Facial recognition (unlocking phones, security), medical imaging (tumour detection), autonomous vehicles (object detection).
  • Natural Language Processing (NLP): Machine translation (Google Translate), sentiment analysis, chatbots, text summarization.
  • Game playing: Deep Blue (chess), AlphaGo (Go), AlphaStar (StarCraft II) — demonstrated superhuman performance in complex games.

1.3 Robotics & Automation

  • Industrial robots: Automated assembly lines, welding, painting. Increase precision and speed; operate in hazardous environments.
  • Service robots: Vacuum cleaners (Roomba), lawn mowers, delivery drones, warehouse robots (Amazon Kiva).
  • Medical robots: Surgical assistants (da Vinci), rehabilitation exoskeletons, robotic prosthetics.
  • Autonomous vehicles: Self-driving cars (Tesla Autopilot, Waymo) use sensors (LIDAR, cameras, radar), GPS, and AI to navigate.

1.4 Internet of Things (IoT)

Network of physical devices embedded with sensors, software, and connectivity to exchange data.

  • Smart home: Thermostats (Nest), lighting (Philips Hue), security cameras, smart locks, voice-controlled appliances.
  • Smart cities: Traffic monitoring, intelligent street lighting, waste management sensors, air quality monitors.
  • Wearables: Fitness trackers (Fitbit), smartwatches (Apple Watch), health monitors.
  • Industrial IoT (IIoT): Predictive maintenance, supply chain tracking, quality monitoring.

📗 AS Level Content

2.1 Machine Learning (ML)

A subset of AI where systems learn from data rather than being explicitly programmed.

  • Supervised learning: Model trained on labelled data (input + correct output). Learns to map inputs to outputs.
    • Classification: Predict discrete categories (spam/not spam, disease/no disease). Algorithms: Decision Trees, Random Forest, SVM, Neural Networks.
    • Regression: Predict continuous values (house price, temperature). Algorithms: Linear Regression, Polynomial Regression.
  • Unsupervised learning: Model finds patterns in unlabelled data.
    • Clustering: Group similar data points (customer segmentation). Algorithms: K-Means, Hierarchical Clustering.
    • Dimensionality reduction: Reduce features while preserving information (PCA).
  • Reinforcement learning: Agent learns by interacting with environment, receiving rewards/penalties. Used in game playing, robotics, recommendation systems.

2.2 Neural Networks & Deep Learning

  • Artificial Neural Network (ANN): Inspired by biological neurons. Layers of interconnected nodes (neurons).
    • Input layer: Receives raw data features.
    • Hidden layers: Process and transform data. More layers = "deep" learning.
    • Output layer: Produces final prediction.
  • Training process:
    1. Forward pass: input flows through network, producing output.
    2. Calculate loss: difference between prediction and actual (e.g., Mean Squared Error, Cross-Entropy).
    3. Backpropagation: calculate gradient of loss with respect to each weight.
    4. Gradient descent: adjust weights to minimize loss. Learning rate controls step size.
  • Overfitting: Model memorizes training data but fails on new data. Solutions: more training data, regularization (L1/L2), dropout, early stopping, cross-validation.
  • Underfitting: Model too simple to capture patterns. Solutions: more complex model, more features, longer training.

2.3 Natural Language Processing (NLP) Deep Dive

  • Tokenization: Splitting text into words or subwords.
  • Word embeddings: Represent words as dense vectors capturing semantic meaning (Word2Vec, GloVe). Similar words have similar vectors.
  • Transformers: Architecture enabling parallel processing and attention mechanisms. "Attention is All You Need" (Vaswani et al., 2017).
  • Large Language Models (LLMs): GPT-4, Claude, LLaMA. Trained on massive text corpora. Capabilities: generation, summarization, translation, reasoning, code generation. Limitations: hallucination, bias, lack of true understanding.

2.4 Computer Vision Techniques

  • Convolutional Neural Networks (CNNs): Specialized for image data. Convolutional layers detect features (edges, textures, shapes). Pooling layers reduce dimensionality. Popular architectures: LeNet, AlexNet, VGG, ResNet, EfficientNet.
  • Object detection: YOLO (You Only Look Once), R-CNN. Identifies and locates multiple objects in images.
  • Image segmentation: Pixel-level classification. Semantic segmentation (class per pixel) vs Instance segmentation (individual object masks).
  • Generative models: GANs (Generative Adversarial Networks — generator vs discriminator), Diffusion Models (DALL-E, Stable Diffusion, Midjourney).

📙 A2 Level Content

3.1 Advanced AI Concepts

  • Federated Learning: Train models across decentralized devices without centralizing raw data. Privacy-preserving. Used by Google Gboard, Apple Siri.
  • Transfer Learning: Pre-train on large dataset, fine-tune on smaller specific dataset. Dramatically reduces training data requirements.
  • AutoML: Automated machine learning — algorithms select models, tune hyperparameters, engineer features automatically.
  • Neuromorphic Computing: Hardware mimicking brain architecture (spiking neural networks). Extremely energy-efficient for edge AI (Intel Loihi, IBM TrueNorth).
  • Quantum Machine Learning: Using quantum computers to accelerate certain ML tasks. Promising for optimization and linear algebra but still experimental.

3.2 Ethical AI & Governance

  • AI Bias: Training data reflects historical biases → discriminatory outcomes. Examples: facial recognition less accurate for darker skin; hiring algorithms penalizing women; predictive policing targeting minorities.
    • Mitigation: Diverse training data, bias auditing, fairness constraints, explainable models, diverse development teams.
  • Explainability (XAI): Understanding why AI made a decision. Critical for healthcare, finance, legal. Techniques: SHAP, LIME, attention visualization.
  • AI Governance frameworks:
    • EU AI Act (2024): Risk-based regulation — prohibited, high-risk, limited-risk, minimal-risk categories.
    • US Executive Order on AI (2023): Safety testing, standards, watermarking AI-generated content.
    • UN recommendations: Human rights-based approach to AI.
  • Autonomous weapons: Lethal autonomous weapons systems (LAWS). Campaign to Stop Killer Robots. Debate: deterrence vs loss of human control, accountability gap.

3.3 Blockchain & Decentralized Technologies

  • Blockchain: Distributed, immutable ledger. Blocks chained via cryptographic hashes. Consensus mechanisms: Proof of Work (energy-intensive, Bitcoin), Proof of Stake (energy-efficient, Ethereum 2.0).
  • Smart contracts: Self-executing code on blockchain (Ethereum). Automatically enforce agreements without intermediaries.
  • NFTs (Non-Fungible Tokens): Unique digital ownership certificates. Used for art, collectibles, gaming items. Controversial due to speculation and environmental concerns.
  • DeFi (Decentralized Finance): Financial services (lending, borrowing, trading) on blockchain without traditional banks. High risk, regulatory uncertainty.
  • Use cases beyond crypto: Supply chain transparency, voting systems, digital identity, healthcare records, intellectual property.

3.4 Biotechnology & Human Enhancement

  • Brain-Computer Interfaces (BCIs): Direct communication between brain and computer. Neuralink, Synchron. Applications: paralysis treatment, prosthetic control, eventually cognitive enhancement.
  • CRISPR & gene editing: AI accelerates genetic research and drug discovery. Ethical concerns: designer babies, genetic discrimination, unintended mutations.
  • Wearable & implantable tech: Smart contact lenses, continuous glucose monitors, implantable RFID chips. Privacy and bodily autonomy concerns.

3.5 Evaluating Emerging Technologies

When assessing new technologies, consider the STEEPLE framework:

  • Social: Impact on communities, inequality, digital divide, employment.
  • Technological: Maturity, reliability, scalability, interoperability.
  • Economic: Cost, ROI, market disruption, new business models.
  • Environmental: Energy consumption, e-waste, resource extraction, carbon footprint.
  • Political: Regulation, geopolitical competition, state surveillance.
  • Legal: Liability, intellectual property, compliance, jurisdiction.
  • Ethical: Autonomy, privacy, fairness, transparency, human dignity.
