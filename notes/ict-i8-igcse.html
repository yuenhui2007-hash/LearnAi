📘 Subject Context

Programming Concepts & Algorithms is a fundamental topic in IGCSE ICT. Understanding both the theory and practical applications of information and communication technology is essential for the modern world and the examination.

IGCSE ICT tests theoretical knowledge, practical skills, and the ability to apply ICT to solve problems. Paper 1 (Theory) tests knowledge and understanding; Paper 2 (Practical) tests hands-on skills in word processing, spreadsheets, databases, and presentations.

Programming Concepts & Algorithms

Topic i8 — Computational Thinking, Programming & Problem Solving

📘 IGCSE Content

1.1 Computational Thinking

The thought process involved in formulating problems and their solutions so that the solutions are represented in a form that can be effectively carried out by an information-processing agent.

  • Decomposition: Breaking a complex problem into smaller, manageable sub-problems. Example: A game = menu system + graphics engine + physics + scoring.
  • Abstraction: Removing unnecessary detail to focus on essential features. Example: Representing a road map without showing every building.
  • Pattern Recognition: Identifying similarities or trends across problems or data. Example: Recognizing that sorting is needed in multiple parts of a program.
  • Algorithmic Thinking: Developing step-by-step instructions to solve a problem.

1.2 Algorithms

An algorithm is a finite sequence of well-defined instructions to solve a problem. Characteristics: unambiguous, finite steps, deterministic, produces output.

Ways to represent algorithms:

  • Pseudocode: Structured English-like description. Not tied to any programming language.
    INPUT number
    IF number MOD 2 = 0 THEN
    OUTPUT "Even"
    ELSE
    OUTPUT "Odd"
    ENDIF
  • Flowcharts: Visual representation using standard symbols.
    • Oval = Start/End
    • Rectangle = Process
    • Diamond = Decision
    • Parallelogram = Input/Output
    • Arrows = Flow direction

1.3 Programming Constructs

  • Sequence: Instructions executed one after another in order.
  • Selection (Decision): IF...THEN...ELSE, CASE/SWITCH. Chooses different paths based on conditions.
    IF score >= 80 THEN
    grade = "A"
    ELSE IF score >= 70 THEN
    grade = "B"
    ELSE
    grade = "C"
    ENDIF
  • Iteration (Looping):
    • FOR loop: Count-controlled. Known number of repetitions. FOR i = 1 TO 10 ... ENDFOR
    • WHILE loop: Condition-controlled. Checks before each iteration. WHILE count < 5 ... ENDWHILE
    • REPEAT...UNTIL: Condition-controlled. Checks after each iteration (always runs at least once). REPEAT ... UNTIL count >= 5

1.4 Variables, Constants & Data Types

  • Variable: Named storage location whose value can change during program execution.
  • Constant: Named value that does not change. Declared once, used throughout. Improves readability and maintainability.
  • Data Types:
    • Integer: Whole numbers (positive or negative).
    • Real/Float: Numbers with decimal points.
    • String: Text enclosed in quotes.
    • Boolean: TRUE or FALSE.
    • Char: Single character.

1.5 Basic Operations

  • Arithmetic: +, −, *, /, DIV (integer division), MOD (remainder), ^ (power).
  • Relational: =, <>, <, >, <=, >= (compare values, return Boolean).
  • Logical: AND, OR, NOT (combine Boolean expressions).
  • Assignment: variable ← value or variable = value.
  • Input/Output: INPUT, OUTPUT, PRINT, DISPLAY, READ, WRITE.

1.6 Arrays

An array is a collection of elements of the same data type stored under one name, accessed by index.

DECLARE names[5] : STRING // array of 5 strings, indices 0 to 4
names[0] = "Alice"
names[1] = "Bob"
FOR i = 0 TO 4
OUTPUT names[i]
ENDFOR

1D arrays: Single list. 2D arrays: Table with rows and columns (e.g., game board, spreadsheet data).

📗 AS Level Content

2.1 Structured Programming

  • Modular design: Breaking programs into functions/procedures/modules. Each module has a single, well-defined purpose.
  • Function: Returns a value. Can be used in expressions. Example: y = Sqrt(x)
  • Procedure/Subroutine: Performs a task but does not return a value directly. Called to execute actions.
  • Parameters: Values passed to functions/procedures.
    • By Value: Copy of data passed; original unchanged.
    • By Reference: Address passed; changes affect original variable.
  • Local variables: Declared inside a function; exist only during function execution. Prevent naming conflicts.
  • Global variables: Accessible everywhere. Convenient but risky — can be modified unexpectedly; harder to debug.

2.2 String Handling & File Operations

  • String operations: LENGTH("Hello") → 5, LEFT("Hello",2) → "He", RIGHT("Hello",2) → "lo", MID("Hello",2,3) → "ell", UPPER/LOWER, ASC("A") → 65, CHR(65) → "A", NUM_TO_STRING, STRING_TO_NUM.
  • File handling: OPENFILE filename FOR READ/WRITE/APPEND, READFILE, WRITEFILE, CLOSEFILE, EOF (end of file marker).
OPENFILE "scores.txt" FOR READ
WHILE NOT EOF("scores.txt")
READFILE "scores.txt", line
OUTPUT line
ENDWHILE
CLOSEFILE "scores.txt"

2.3 Searching Algorithms

  • Linear Search: Check each element in order from start to end. Simple; works on unsorted data. Time complexity: O(n).
    found = FALSE
    i = 0
    WHILE i < length AND NOT found
    IF array[i] = target THEN
    found = TRUE
    index = i
    ENDIF
    i = i + 1
    ENDWHILE
  • Binary Search: Requires sorted data. Repeatedly divides search interval in half. Time complexity: O(log n). Much faster for large datasets.
    low = 0
    high = length - 1
    found = FALSE
    WHILE low <= high AND NOT found
    mid = (low + high) DIV 2
    IF array[mid] = target THEN
    found = TRUE
    ELSE IF array[mid] < target THEN
    low = mid + 1
    ELSE
    high = mid - 1
    ENDIF
    ENDWHILE

2.4 Sorting Algorithms

  • Bubble Sort: Repeatedly swap adjacent elements if in wrong order. After each pass, largest unsorted element "bubbles" to end. Time: O(n²). Simple but inefficient.
    FOR pass = 1 TO n-1
    FOR i = 0 TO n-pass-1
    IF array[i] > array[i+1] THEN
    temp = array[i]
    array[i] = array[i+1]
    array[i+1] = temp
    ENDIF
    NEXT i
    NEXT pass
  • Insertion Sort: Build sorted array one element at a time. Take next element, insert into correct position in sorted portion. Time: O(n²) worst, O(n) best (already sorted). Efficient for small or nearly sorted data.
    FOR i = 1 TO n-1
    current = array[i]
    j = i - 1
    WHILE j >= 0 AND array[j] > current
    array[j+1] = array[j]
    j = j - 1
    ENDWHILE
    array[j+1] = current
    NEXT i

2.5 Error Types

  • Syntax error: Code breaks language rules (missing bracket, misspelled keyword). Caught by compiler/interpreter before execution.
  • Runtime error: Occurs during execution (division by zero, file not found, array index out of bounds). Program crashes or behaves unexpectedly.
  • Logic error: Program runs but produces incorrect results. Hardest to find. Caused by flawed algorithm or incorrect conditions. Found through testing and debugging.

📙 A2 Level Content

3.1 Advanced Sorting & Searching

  • Merge Sort: Divide-and-conquer. Split array in half recursively, sort each half, merge sorted halves. Time: O(n log n) in all cases. Stable sort. Requires O(n) extra space.
    MERGE_SORT(array):
    IF length <= 1 THEN RETURN array
    mid = length DIV 2
    left = MERGE_SORT(array[0:mid])
    right = MERGE_SORT(array[mid:length])
    RETURN MERGE(left, right)
    MERGE(left, right):
    result = []
    WHILE left not empty AND right not empty
    IF left[0] <= right[0] THEN append left[0] to result, remove left[0]
    ELSE append right[0] to result, remove right[0]
    append remaining elements
    RETURN result
  • Quick Sort: Divide-and-conquer. Choose pivot, partition array into elements < pivot and >= pivot, recursively sort partitions. Time: O(n log n) average, O(n²) worst (poor pivot choice). In-place (low space). Not stable.
  • Hashing: Map keys to array indices using hash function. Ideal search time: O(1). Collisions resolved by chaining (linked lists) or open addressing (probing).

3.2 Abstract Data Types (ADTs)

  • Stack: LIFO (Last In, First Out). Operations: PUSH (add to top), POP (remove from top), PEEK (view top). Used: undo operations, function call stack, expression evaluation, backtracking.
    Stack: []
    PUSH 5 → [5]
    PUSH 3 → [5, 3]
    POP → returns 3, stack is [5]
    PEEK → returns 5
  • Queue: FIFO (First In, First Out). Operations: ENQUEUE (add to rear), DEQUEUE (remove from front), FRONT (view front). Used: print queues, CPU scheduling, BFS traversal, buffering.
    Queue: []
    ENQUEUE A → [A]
    ENQUEUE B → [A, B]
    DEQUEUE → returns A, queue is [B]
  • Linked List: Nodes containing data and pointer to next node. Dynamic size. Types: singly linked (one pointer), doubly linked (previous and next), circular. No random access — must traverse from head.
  • Tree: Hierarchical structure. Root node, parent-child relationships. Binary Tree: each node has at most 2 children. Binary Search Tree (BST): left < parent < right. Enables efficient search, insertion, deletion (O(log n) balanced).

3.3 Graph Algorithms

  • Graph representation: Adjacency matrix (2D array, fast edge check, O(V²) space) or Adjacency list (linked lists per vertex, space-efficient for sparse graphs).
  • Breadth-First Search (BFS): Uses queue. Explores all neighbours at current depth before moving deeper. Finds shortest path in unweighted graphs.
  • Depth-First Search (DFS): Uses stack (or recursion). Explores as far as possible along each branch before backtracking. Used for maze solving, topological sort, cycle detection.
  • Dijkstra's Algorithm: Finds shortest path from source to all vertices in weighted graph with non-negative weights. Uses priority queue (min-heap). Time: O((V+E) log V).

3.4 Object-Oriented Programming (OOP)

  • Class: Blueprint defining attributes (data) and methods (behaviour).
  • Object: Instance of a class.
  • Encapsulation: Bundling data and methods; hiding internal state (private/protected); exposing interfaces (public methods/getters/setters).
  • Inheritance: Subclass derives from superclass, inheriting attributes and methods. Enables code reuse and "is-a" relationships. Example: Car inherits from Vehicle.
  • Polymorphism: Same interface, different implementations. Method overriding (subclass redefines parent method) and method overloading (same name, different parameters).
  • Abstraction: Simplifying complex reality by modelling classes appropriate to the problem.

3.5 Recursion

A function that calls itself. Must have:

  • Base case: Condition that stops recursion.
  • Recursive case: Function calls itself with a simpler sub-problem.
FUNCTION factorial(n)
IF n <= 1 THEN
RETURN 1
ELSE
RETURN n * factorial(n - 1)
ENDIF
ENDFUNCTION

factorial(5) = 5 × 4 × 3 × 2 × 1 = 120

Other examples: Fibonacci, binary search, merge sort, tree traversals, Tower of Hanoi.

Pros: Elegant, mirrors mathematical definitions, reduces code. Cons: Stack overflow risk, can be slower than iteration, harder to debug.

💻 Worked Example

Question: Convert denary 157 to 8-bit binary.

Solution:
128 + 16 + 8 + 4 + 1 = 157
1 0 0 1 1 1 0 1
Answer: 10011101
Confusing bits and bytes. 1 byte = 8 bits. File sizes in bytes; transfer speeds in bits.
Fetch-decode-execute: 1) Fetch instruction from memory, 2) Decode operation, 3) Execute. Repeats millions of times/second.

⚡ Quick Recall

  • CPU: ALU + CU + Registers
  • RAM: Volatile; ROM: Non-volatile
  • LAN: Local; WAN: Wide
  • Binary to hex: Group in 4s from right

⚠️ Common Mistakes to Avoid

  • Confusing an intranet (internal network) with the Internet (global network).
  • Forgetting to convert between binary, denary, and hexadecimal — practise these conversions regularly.
  • Using "hacking" as a generic term — be specific about the type of threat (virus, phishing, malware, etc.).
  • Mixing up the functions of the CPU components — ALU (calculations), CU (control), Registers (temporary storage).
  • Confusing verification (checking data is entered correctly) with validation (checking data is reasonable).

✅ Key Points to Remember

  • Be able to convert between binary, denary, and hexadecimal number systems.
  • Understand the threats to computer systems and the methods used to protect against them.
  • Be able to create and modify spreadsheets, databases, and presentations in the practical examination.
  • Know the advantages and disadvantages of different input and output devices for specific situations.
  • Know the stages of the systems development life cycle and what happens at each stage.

🎯 Examination Tips

  • In theory questions, use precise terminology — "volatile" not "forgets data when switched off".
  • Check your files before finishing the practical exam — ensure they are saved in the correct format and location.
  • In practical examinations, follow the instructions exactly — missing a small step can lose marks.
  • In spreadsheet questions, be able to use formulae, functions (SUM, AVERAGE, IF, etc.), and create charts.
  • For presentation questions, apply design principles — consistency, readability, appropriate use of images.
