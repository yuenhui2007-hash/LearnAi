Databases & Data Management

Topic i5 — Revision Summary

📝 Last-Minute Summary

  • Relational databases use multiple linked tables; flat files are single-table and redundant.
  • Primary key uniquely identifies; foreign key links tables.
  • Relationships: 1:1, 1:M, M:N (needs junction table).
  • Normalisation: 1NF (atomic), 2NF (no partial dependency), 3NF (no transitive dependency).
  • SQL commands: SELECT, INSERT, UPDATE, DELETE, CREATE TABLE, ALTER, JOIN, GROUP BY, HAVING.
  • Validation: range, type, length, presence, format, lookup, check digit.
  • ACID: Atomicity, Consistency, Isolation, Durability.
  • Indexing speeds queries but slows writes.
  • NoSQL scales horizontally; document, key-value, column, graph types.
  • Exam tip: Always state primary and foreign keys when designing a database. Draw ERDs with crow's foot notation.

🔑 Key Terms

  • Table, Record, Field, Tuple, Attribute, Primary Key, Foreign Key, Composite Key
  • 1NF, 2NF, 3NF, Normalisation, Redundancy, Transitive dependency
  • SQL, SELECT, WHERE, JOIN, INNER JOIN, GROUP BY, HAVING, COUNT, AVG, MAX
  • ACID, Transaction, Index, B-tree, Query optimiser
  • ERD, Crow's foot, Cardinality, Junction table
  • NoSQL, MongoDB, CAP Theorem, Sharding, Replication

🎯 Exam Tips

  • Design questions: identify entities, attributes, keys, then draw relationships.
  • SQL: remember ORDER BY, GROUP BY, and HAVING syntax order.
  • Normalisation: explain WHY each step removes redundancy — not just what.
  • For M:N relationships, always introduce a junction/link table.
