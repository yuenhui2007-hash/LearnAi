Web Design & HTML/CSS

Topic i6 — Web Technologies, Standards & Development

📘 IGCSE Content

1.1 How the Web Works

  • Client-server model: Browser (client) requests pages; web server (e.g., Apache, Nginx, IIS) responds with files.
  • HTTP (HyperText Transfer Protocol): Stateless request-response protocol. Port 80. HTTPS = encrypted via TLS, port 443.
  • URL anatomy: https://www.example.com:443/products?id=42 → protocol + subdomain + domain + TLD + port + path + query string.
  • DNS resolution: Browser checks cache → OS cache → router cache → ISP DNS → recursive query to authoritative DNS → IP address returned.
  • Web hosting: Shared (cheap, limited), VPS (virtual private), Dedicated (full server), Cloud (scalable, pay-as-you-go).

1.2 HTML Basics

HTML (HyperText Markup Language) structures web content using elements (tags).

<!DOCTYPE html>
<html lang="en">
<head>
<meta charset="UTF-8">
<title>My Page</title>
</head>
<body>
<h1>Heading</h1>
<p>This is a <strong>paragraph</strong> with <em>emphasis</em>.</p>
<a href="https://example.com">Link</a>
<img src="photo.jpg" alt="Description" width="300">
<ul><li>Item 1</li><li>Item 2</li></ul>
</body>
</html>

1.3 Common HTML Elements

  • Structural: <header>, <nav>, <main>, <section>, <article>, <aside>, <footer> — semantic HTML5.
  • Text: <h1> to <h6>, <p>, <br>, <hr>, <blockquote>, <pre>.
  • Formatting: <strong>/<b>, <em>/<i>, <mark>, <small>, <sub>, <sup>.
  • Lists: <ul> (unordered/bullet), <ol> (ordered/numbered), <li> (list item), <dl>/<dt>/<dd> (definition list).
  • Links: <a href="..." target="_blank"> — target values: _self, _blank, _parent, _top.
  • Images & Media: <img> (src, alt, width, height), <audio> (controls, src), <video> (controls, width, height, poster).
  • Tables: <table>, <tr> (row), <th> (header), <td> (data), <caption>, <thead>, <tbody>, <tfoot>.
  • Forms: <form> (action, method="GET/POST"), <input> (type: text, password, email, number, checkbox, radio, date, file, submit), <textarea>, <select>/<option>, <label> (for attribute links to input id).

1.4 Introduction to CSS

CSS (Cascading Style Sheets) controls presentation. Three ways to apply:

  • Inline: <p style="color:red;"> — highest specificity, hard to maintain.
  • Internal: <style> in <head> — for single-page sites.
  • External: <link rel="stylesheet" href="styles.css"> — preferred for multi-page sites; separation of concerns.

CSS Syntax:

selector {
property: value;
property2: value2;
}

/* Examples */
h1 { color: navy; font-size: 24px; }
.intro { background-color: #f0f0f0; padding: 10px; }
#header { width: 100%; height: 60px; }

1.5 CSS Selectors

  • Element: p, h1, div — selects all of that element.
  • Class: .classname — reusable; multiple elements can share.
  • ID: #idname — unique per page; highest specificity.
  • Descendant: div p — selects <p> inside <div>.
  • Child: div > p — direct child only.
  • Adjacent sibling: h1 + p — <p> immediately after <h1>.
  • Attribute: [type="submit"], [href^="https"] — based on attributes.
  • Pseudo-class: :hover, :focus, :nth-child(odd), :first-child.
  • Pseudo-element: ::before, ::after, ::first-line.

📗 AS Level Content

2.1 CSS Box Model

Every element is a rectangular box:

Total width = content width + padding-left + padding-right + border-left + border-right + margin-left + margin-right
box-sizing: border-box; /* includes padding and border in width */
  • Content: Text, images, or other media.
  • Padding: Space between content and border (inside the box).
  • Border: Line around padding. Properties: width, style (solid, dashed, dotted), color.
  • Margin: Space outside the border, separating elements. Margin collapse occurs when vertical margins overlap.

2.2 CSS Layout Techniques

  • Display property: block (full width), inline (within text flow), inline-block (inline but accepts dimensions), none (hidden), flex, grid.
  • Positioning:
    • Static: Default; normal document flow.
    • Relative: Offset from normal position (top, left, etc.).
    • Absolute: Positioned relative to nearest positioned ancestor.
    • Fixed: Relative to viewport; stays on screen when scrolling.
    • Sticky: Toggles between relative and fixed based on scroll position.
  • Float: Older layout method; moves element left/right with text wrapping. Clearfix needed. Largely replaced by Flexbox/Grid.
  • Flexbox: One-dimensional layout (row or column). Properties: display:flex, justify-content, align-items, flex-direction, flex-wrap, gap.
  • CSS Grid: Two-dimensional layout (rows and columns). Properties: display:grid, grid-template-columns, grid-template-rows, grid-gap, grid-area.

2.3 Responsive Web Design (RWD)

Websites adapt to different screen sizes:

  • Viewport meta tag: <meta name="viewport" content="width=device-width, initial-scale=1.0">
  • Media queries: Apply CSS conditionally based on device characteristics.
    @media screen and (max-width: 600px) {
    nav { flex-direction: column; }
    body { font-size: 14px; }
    }
  • Fluid layouts: Use percentages, vw/vh, fr units instead of fixed pixels.
  • Flexible images: max-width: 100%; height: auto; prevents overflow.
  • Mobile-first approach: Design for small screens first, then enhance for larger screens with min-width media queries.

2.4 JavaScript Fundamentals

JavaScript adds interactivity to web pages. It runs in the browser (client-side) or on servers (Node.js).

// Variables
let name = "Alice"; // block-scoped, reassignable
const PI = 3.14159; // block-scoped, constant
var count = 0; // function-scoped (legacy)

// Functions
function greet(user) {
return "Hello, " + user;
}
const add = (a, b) => a + b;

// DOM manipulation
document.getElementById("btn").addEventListener("click", function() {
document.querySelector(".message").textContent = "Clicked!";
});

// Conditionals & loops
if (score >= 50) { status = "Pass"; }
for (let i = 0; i < 5; i++) { console.log(i); }

2.5 Web Standards & Accessibility

  • W3C: World Wide Web Consortium sets standards (HTML, CSS, WCAG).
  • WCAG (Web Content Accessibility Guidelines): Perceivable, Operable, Understandable, Robust (POUR).
  • Accessibility techniques: Alt text for images, semantic HTML, ARIA labels, keyboard navigation, sufficient colour contrast (4.5:1 minimum), resizable text.
  • Validation: W3C Markup Validator checks HTML; CSS Validator checks stylesheets.

📙 A2 Level Content

3.1 Server-Side Technologies

  • Server-side scripting: Code executed on the server before HTML is sent to client. Enables dynamic content, database access, user authentication.
  • PHP: Widely used, embedded in HTML. Connects to MySQL easily. Example:
    <?php
    $conn = new mysqli("localhost", "user", "pass", "db");
    $result = $conn->query("SELECT * FROM Students");
    while($row = $result->fetch_assoc()) {
    echo "<p>" . $row["FirstName"] . "</p>";
    }
    ?>
  • Python (Flask/Django): Flask is lightweight micro-framework; Django is full-featured with ORM, admin panel, security built-in.
  • Node.js + Express: JavaScript on the server. Non-blocking I/O, event-driven. JSON-native.
  • ASP.NET: Microsoft's framework for C# web applications.

3.2 Databases & Web Integration

  • CRUD operations: Create (INSERT), Read (SELECT), Update (UPDATE), Delete (DELETE).
  • SQL Injection: Malicious input manipulating queries. Prevention: parameterized queries/prepared statements.
    // Vulnerable
    $query = "SELECT * FROM Users WHERE username='" . $_GET['u'] . "'";

    // Secure (parameterized)
    $stmt = $pdo->prepare("SELECT * FROM Users WHERE username = ?");
    $stmt->execute([$_GET['u']]);
  • Session management: HTTP is stateless; sessions (server-side) and cookies (client-side) maintain state. Session ID stored in cookie; data stored server-side.
  • JSON & AJAX: Asynchronous JavaScript and XML (now mostly JSON). Fetch API retrieves data without full page reload.
    fetch('/api/data')
    .then(response => response.json())
    .then(data => console.log(data));

3.3 Web Security

  • XSS (Cross-Site Scripting): Injecting malicious scripts into web pages viewed by others. Prevention: escape output, Content Security Policy (CSP), validate input.
  • CSRF (Cross-Site Request Forgery): Tricking authenticated users into unwanted actions. Prevention: CSRF tokens, SameSite cookies.
  • HTTPS/TLS: Encrypts data in transit. Certificates from CAs. HSTS header forces HTTPS.
  • Password security: Hash with bcrypt/Argon2 (slow, salted). Never store plaintext. Implement rate limiting on login attempts.

3.4 APIs & Modern Web Architecture

  • REST (Representational State Transfer): Stateless architecture using HTTP methods: GET (read), POST (create), PUT/PATCH (update), DELETE (remove). Resources identified by URLs. Returns JSON/XML.
  • GraphQL: Query language allowing clients to request exactly the data they need. Single endpoint. Reduces over-fetching.
  • WebSockets: Full-duplex persistent connection for real-time data (chat, gaming, live updates).
  • Progressive Web Apps (PWA): Web apps that work offline, send push notifications, install to home screen. Use service workers and manifest files.

3.5 Search Engine Optimisation (SEO)

  • On-page: Title tags, meta descriptions, header hierarchy, keyword-rich content, alt text, internal links, clean URLs, fast loading (Core Web Vitals).
  • Technical: Mobile-friendly, HTTPS, XML sitemap, robots.txt, structured data (Schema.org), canonical tags.
  • Off-page: Backlinks from reputable sites, social signals, domain authority.

💻 Worked Example

Question: Convert denary 157 to 8-bit binary.

Solution:
128 + 16 + 8 + 4 + 1 = 157
1 0 0 1 1 1 0 1
Answer: 10011101
Confusing bits and bytes. 1 byte = 8 bits. File sizes in bytes; transfer speeds in bits.
Fetch-decode-execute: 1) Fetch instruction from memory, 2) Decode operation, 3) Execute. Repeats millions of times/second.
