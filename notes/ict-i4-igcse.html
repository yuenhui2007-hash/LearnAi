📘 Subject Context

Software, OS & Applications is a fundamental topic in IGCSE ICT. Understanding both the theory and practical applications of information and communication technology is essential for the modern world and the examination.

IGCSE ICT tests theoretical knowledge, practical skills, and the ability to apply ICT to solve problems. Paper 1 (Theory) tests knowledge and understanding; Paper 2 (Practical) tests hands-on skills in word processing, spreadsheets, databases, and presentations.

Software, OS & Applications

Topic i4 — Systems Software, Utilities & Application Software

📘 IGCSE Content

1.1 Types of Software

  • System software: Manages hardware and provides platform for applications. Includes operating systems, device drivers, utilities.
  • Application software: Programs users run to perform tasks. General-purpose (word processor, spreadsheet) or special-purpose (payroll, booking system).

1.2 Operating System (OS) Functions

The OS is the intermediary between user and hardware. Core functions:

  • Memory management: Allocates RAM to processes; virtual memory; paging/segmentation.
  • Processor management: Scheduling (FIFO, SJF, round robin, priority); multitasking; interrupt handling.
  • File management: Organizes storage with directories/folders; file permissions; maintains file allocation table.
  • Device management: Controls peripherals via device drivers; buffers and spooling (e.g., print queue).
  • Security: User accounts, passwords, access rights, encryption.
  • User interface: GUI (windows, icons, menus, pointers), CLI (command line), voice, touch.

1.3 Utility Programs

  • Disk defragmenter: Reorganizes fragmented files into contiguous blocks on HDD. Improves read speed. Not needed for SSDs.
  • Disk cleanup: Removes temporary files, recycle bin contents, cache.
  • Backup software: Copies data to secondary location. Full, incremental, differential strategies.
  • Compression utilities: Reduce file size (ZIP, RAR) for storage or transmission.
  • Antivirus / Anti-malware: Scans, detects, quarantines threats.
  • Firewall: Filters network traffic.
  • System monitors: Task Manager, Resource Monitor — show CPU, RAM, disk, network usage.

1.4 Application Software Types

  • Word processing: Create, edit, format text documents. Features: spell check, mail merge, styles, tables, macros. Examples: Microsoft Word, Google Docs.
  • Spreadsheets: Grid of cells for calculations, charts, data analysis. Features: formulas, functions, pivot tables, conditional formatting. Examples: Excel, Google Sheets.
  • Presentation: Slides with text, images, animations. Examples: PowerPoint, Google Slides.
  • Database management: Store, query, and manage structured data. Examples: Access, MySQL, FileMaker.
  • Web browsers: Access and render web pages. Examples: Chrome, Firefox, Edge, Safari.
  • Email clients: Send/receive/manage emails. Examples: Outlook, Thunderbird, Apple Mail.
  • Graphics editing: Bitmap (Photoshop, GIMP) and vector (Illustrator, Inkscape).
  • Video editing: Timeline-based editing, transitions, effects. Examples: Premiere Pro, DaVinci Resolve, iMovie.

📗 AS Level Content

2.1 OS Scheduling Algorithms

  • First-Come First-Served (FCFS): Simple queue. Easy to implement but can cause convoy effect (short jobs wait behind long ones).
  • Shortest Job First (SJF): Minimizes average waiting time. Requires prediction of burst time. Can starve long jobs.
  • Round Robin: Fixed time quantum (e.g., 10ms) per process; cycles through queue. Fair, good response time; context-switch overhead.
  • Priority Scheduling: Highest priority runs first. Can be preemptive or non-preemptive. Risk of starvation for low-priority processes.
  • Multilevel Queue: Multiple queues with different priorities (e.g., system, interactive, batch, student).

2.2 Memory Management Techniques

  • Single contiguous allocation: Entire memory to one program. Simple but wasteful.
  • Partitioned allocation: Fixed partitions (wastes space if program smaller) or dynamic partitions (fragmentation).
  • Paging: Physical memory divided into fixed-size frames; logical memory into same-size pages. Page table maps pages to frames. Eliminates external fragmentation.
  • Segmentation: Logical memory divided into variable-size segments (code, data, stack). Segment table maps segments to physical addresses. Matches program structure but can cause external fragmentation.
  • Virtual memory: Uses disk as extension of RAM. Page fault = needed page not in RAM; OS fetches from disk. Thrashing = excessive page faults degrade performance.

2.3 File Systems & Storage

  • FAT32: Older, compatible everywhere. 4GB max file size, 2TB max partition. No journaling.
  • NTFS (Windows): Journaling, encryption (EFS), compression, permissions, large file support.
  • ext4 (Linux): Journaling, extents, large volume/file support, backward compatible.
  • APFS (macOS): Optimized for SSDs, snapshots, encryption, space sharing.
  • Journaling: Logs changes before applying them. Prevents corruption from power failure.

2.4 Translation Software

  • Compiler: Translates entire high-level program to machine code before execution. Output = executable file. Slower compilation but faster execution. Detects syntax errors. Examples: GCC, MSVC, Clang.
  • Interpreter: Translates and executes line-by-line. No separate executable. Easier debugging but slower execution. Examples: Python interpreter, JavaScript engine.
  • Assembler: Translates assembly language (mnemonics like MOV, ADD) into machine code (one-to-one). Used for low-level programming.
  • JIT (Just-In-Time) Compiler: Hybrid — compiles bytecode to machine code at runtime. Used by Java (JVM) and C# (.NET CLR).

2.5 Software Licensing

  • Proprietary/Commercial: Closed source; user buys license. Source code not available. Examples: Microsoft Office, Adobe Creative Suite.
  • Open Source: Source code available; can modify and redistribute. Examples: Linux, LibreOffice, GIMP.
  • Freeware: Free to use but source not available. Examples: Skype (originally), Adobe Reader.
  • Shareware: Free trial with limited features or time; pay to unlock. Examples: WinRAR.
  • FOSS (Free and Open Source Software): Free as in freedom (GPL, MIT, Apache licenses).

📙 A2 Level Content

3.1 Real-Time Operating Systems (RTOS)

Guarantees response within strict time constraints. Used in embedded systems, medical devices, automotive, aerospace.

  • Hard real-time: Missing deadline = system failure (e.g., pacemaker, airbag controller).
  • Soft real-time: Missing deadline degrades quality but does not crash (e.g., video streaming, MP3 player).

Features: deterministic scheduling, minimal interrupt latency, priority inheritance, no virtual memory (avoids page faults).

3.2 Distributed Operating Systems

Manages a group of independent computers as a single coherent system. Users perceive it as one machine. Examples: Google File System, Apache Hadoop. Challenges: consensus algorithms, CAP theorem (Consistency, Availability, Partition tolerance — pick two), fault tolerance.

3.3 System Development Life Cycle (SDLC)

  • Waterfall: Linear sequential phases (requirements → design → implementation → testing → deployment → maintenance). Easy to manage; rigid; hard to change requirements later.
  • Agile/Scrum: Iterative sprints (2–4 weeks). Continuous feedback; adaptive; customer collaboration. Roles: Product Owner, Scrum Master, Development Team. Artifacts: Product Backlog, Sprint Backlog, Burndown Chart.
  • Spiral: Risk-driven; combines iterative with systematic risk analysis.
  • RAD (Rapid Application Development): Prototyping focus; quick iterations; user feedback throughout.

3.4 Software Testing

  • White-box: Tester sees internal code. Tests paths, branches, loops. Measures code coverage.
  • Black-box: Tester sees only inputs/outputs. Tests requirements, boundaries, equivalence partitions.
  • Unit testing: Individual functions/modules. Automated with frameworks (JUnit, pytest).
  • Integration testing: Modules combined; test interfaces.
  • System testing: Complete system against specifications.
  • Acceptance testing: User/client validates against business needs.
  • Alpha testing: Internal, controlled environment.
  • Beta testing: Released to external users for real-world feedback.

3.5 Virtualisation & Containers

  • Virtual Machine (VM): Software emulation of a complete computer. Hypervisor (Type 1 = bare metal like VMware ESXi; Type 2 = hosted like VirtualBox) manages VMs. Each VM has its own OS. Heavy resource use.
  • Containers (Docker): Share host OS kernel; package only app + dependencies. Lightweight, fast startup, consistent across environments. Orchestrated by Kubernetes.

💻 Worked Example

Question: Convert denary 157 to 8-bit binary.

Solution:
128 + 16 + 8 + 4 + 1 = 157
1 0 0 1 1 1 0 1
Answer: 10011101
Confusing bits and bytes. 1 byte = 8 bits. File sizes in bytes; transfer speeds in bits.
Fetch-decode-execute: 1) Fetch instruction from memory, 2) Decode operation, 3) Execute. Repeats millions of times/second.

⚡ Quick Recall

  • CPU: ALU + CU + Registers
  • RAM: Volatile; ROM: Non-volatile
  • LAN: Local; WAN: Wide
  • Binary to hex: Group in 4s from right

⚠️ Common Mistakes to Avoid

  • Confusing an intranet (internal network) with the Internet (global network).
  • Confusing bits and bytes — 1 byte = 8 bits. File sizes are in bytes; data transfer speeds are often in bits.
  • Forgetting that a LAN covers a small geographical area while a WAN covers a large area.
  • Using "hacking" as a generic term — be specific about the type of threat (virus, phishing, malware, etc.).
  • Forgetting to convert between binary, denary, and hexadecimal — practise these conversions regularly.

✅ Key Points to Remember

  • Know the hardware components of a computer system and their functions.
  • Know the stages of the systems development life cycle and what happens at each stage.
  • Know the advantages and disadvantages of different input and output devices for specific situations.
  • Be able to create and modify spreadsheets, databases, and presentations in the practical examination.
  • Be able to convert between binary, denary, and hexadecimal number systems.

🎯 Examination Tips

  • Check your files before finishing the practical exam — ensure they are saved in the correct format and location.
  • In spreadsheet questions, be able to use formulae, functions (SUM, AVERAGE, IF, etc.), and create charts.
  • For database questions, know how to create queries using criteria and sorting.
  • In practical examinations, follow the instructions exactly — missing a small step can lose marks.
  • When discussing security, give specific examples — "firewall" is better than "security software".

📝 Last-Minute Summary

  • OS functions: memory, processor, file, device management + security + UI.
  • Scheduling: FCFS, SJF, Round Robin, Priority. Round Robin uses time quantum.
  • Memory management: paging (fixed frames/pages), segmentation (variable), virtual memory (disk extension).
  • Translation: Compiler (whole program → machine code), Interpreter (line-by-line), Assembler (assembly → machine code), JIT (runtime compilation).
  • File systems: FAT32 (old, limited), NTFS (Windows, journaling), ext4 (Linux), APFS (macOS SSD).
  • Licensing: Proprietary, Open Source, Freeware, Shareware. FOSS = free + open.
  • SDLC: Waterfall (linear), Agile/Scrum (iterative sprints), Spiral (risk-driven).
  • Testing: White-box (code visible) vs Black-box (interface only); Unit → Integration → System → Acceptance.
  • Virtualisation: VMs (full OS emulation) vs Containers (shared kernel, lightweight).
  • Exam tip: For OS scheduling questions, always explain the impact on waiting time and turnaround time.
